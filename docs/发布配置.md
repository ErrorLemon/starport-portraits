# GitHub 自动发布配置

目标仓库：ErrorLemon/starport-portraits。以下步骤需由仓库所有者在登录 ErrorLemon 后操作。

## 1. 确认 GitHub 连接

插件连接使用的是授权时选择的 GitHub 账号。若读取仓库返回 404，先核对账号和仓库授权，不必把私有仓库改为公开。

在 GitHub 的 Settings → Applications → Installed GitHub Apps 中，找到对应应用，点击 Configure。在 Repository access 下选择 Only select repositories，将 starport-portraits 加入并保存。如果尚未安装对应应用，应先完成插件的 GitHub 连接和安装授权。

## 2. 设置唯一一个签名 Secret

正式 APK 必须使用原始签名。原始签名备份文件名为 `星港合影-安卓签名备份-请勿分发.zip`，它不在这个源码仓库内。

Mac 上可双击项目根目录的 `复制安卓发布密钥.command`。它会从项目父目录寻找上述 ZIP，把 Base64 文本复制到剪贴板，不会在终端显示密钥或密码。若 ZIP 放在其他目录，使用：

```sh
python3 scripts/copy_signing_secret.py '/实际路径/星港合影-安卓签名备份-请勿分发.zip'
```

然后在仓库网页依次打开：

**Settings → Secrets and variables → Actions → New repository secret**

- Name：`ANDROID_SIGNING_BUNDLE_BASE64`
- Secret：粘贴刚复制的文本。
- 点击 Add secret。

Base64 是用于存储二进制文件的编码；保密依靠 GitHub Actions Secrets。不要将该文本提交到源码、Issue 或聊天中。无需另外创建个人访问令牌，发布步骤使用本次工作流的 GITHUB_TOKEN。

官方说明：https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets

## 3. 首次发布 v0.6.0

首次完整源码合并到 main 时，新增的 release.json 会自动触发 Publish release。等待 Actions 检查和发布均为绿色完成状态，再到 Releases 下载 APK 和电脑版 ZIP。

如果首次运行时还没有配置签名 Secret，先完成第 2 步，再进入失败的 Publish release 运行，点击 Re-run failed jobs。也可以打开 Actions → Publish release → Run workflow，分支选 main，tag 填 v0.6.0。

若缺少签名、版本不一致、已有标签指向其他提交、构建失败或 APK 签名与原版不一致，流程会停止，不会发布不完整的安装包。重复运行已发布版本不会覆盖其下载文件；若发布网络故障留下草稿，请先检查 Releases 中的状态，再决定如何重试。

## 4. 以后更新

由开发者修改功能并测试，增加 versionCode，同步版本号后提交并推送到 main。release.json 的变化会自动触发 Publish release。也可以手动运行，或推送对应版本标签。自动发布不能直接读取电脑上尚未推送的修改。

私有仓库的下载也受仓库权限限制。是否公开仓库由所有者决定；此配置不会修改仓库可见性，也不会开启 GitHub Pages。

## 当前验证范围

工作流应在仓库授权、首次上传与 Secret 设置完成后，进行一次真实 GitHub Actions 运行验证。本地检查或本地 APK 构建通过，不代表已经在 GitHub 成功发布。
